# TUT 0.0.1 Rust Design

**Original decision:** 2026-07-18

**GNU/Unix amendment:** 2026-08-07

**Status:** Implemented design

## 1. Direction

TUT restarts at 0.0.1 as a focused Rust application. The previous C++ browser is historical only and defines no compatibility requirements.

The complete 0.0.1 slice is:

```text
tut FILE → bounded UTF-8 load → width-aware reflow → navigation and literal search
```

TUT follows GNU command-line and build conventions and the Unix principles of one focused job, explicit data flow, predictable status, and no hidden side effects. It is not part of the GNU Project.

## 2. Command-line contract

Supported forms are:

```text
tut FILE
tut -h
tut --help
tut -V
tut --version
tut -- FILE
```

Arguments remain `OsString` values until converted to the original `PathBuf`. A leading-dash filename requires `--`. Unknown options, missing operands, and extra operands exit 2.

Help and version follow GNU output conventions, write standard output, and bypass terminal and file checks. Diagnostics use `tut: message` on standard error. Invocation errors also print the usage synopsis and the standard help hint.

Path and error display is single-line and terminal-safe. C0 and DEL characters become `\xNN`; C1 characters become `\u{NNNN}`. Filesystem access always uses the unmodified path.

Interactive reading requires both stdin and stdout to be terminals. Redirected terminal output and stdin document input are outside 0.0.1.

## 3. File contract

TUT accepts one existing regular file or a symlink resolving to a regular file. The raw limit is exactly 33,554,432 bytes and is not configurable in 0.0.1.

Loading order is deterministic:

1. Open read-only, nonblocking, and close-on-exec.
2. Validate the opened handle as a regular file.
3. Reject metadata already above the limit.
4. Read no more than limit plus one byte.
5. Report size before UTF-8 errors.
6. Validate UTF-8 and report the first invalid raw-byte offset.
7. Remove exactly one leading UTF-8 BOM.
8. Retain the validated bytes in one immutable in-memory `String`.
9. Exclude one leading BOM from the content view while preserving its raw-byte displacement.
10. Project LF, CRLF, and lone CR as structural line endings without rewriting source bytes.

TUT never writes the source, creates user data, accesses the network, or sends telemetry.

## 4. Package and dependencies

TUT is one Cargo package:

```toml
name = "tut"
version = "0.0.1"
edition = "2024"
rust-version = "1.88.0"
publish = false
license = "MIT"
```

The development toolchain is pinned to Rust 1.97.1 with rustfmt and Clippy. `Cargo.lock` is committed.

Production dependencies are Crossterm, Ratatui, rustix, signal-hook, unicode-segmentation, and unicode-width. Development adds tempfile and rustix PTY/process/termios features. There is no async runtime, parser framework, error framework, regex engine, logging framework, or serialization layer.

## 5. Architecture

Dependency direction is:

```text
source -+-> document -+
        +-> layout ----+-> app -> tui
        +-> search ----+
```

`error` is a leaf. `source` defines absolute coordinates and borrowed source spans. Domain modules never import Crossterm or Ratatui. TUI code consumes reader behavior and projection only through `app`, plus typed errors.

Module responsibilities:

- `cli`: pure argument parsing and static help/version text.
- `source`: `u64` source-byte coordinates and validated borrowed source spans.
- `document`: opened-handle validation, bounded reading, the `DocumentStore` boundary, and path metadata.
- `layout`: terminal-safe grapheme and line-ending projection, wrapping, viewport queries, and progress.
- `search`: compact global non-overlapping literal-match indexing.
- `app`: navigation, resize anchoring, search transactions, and immutable render state.
- `tui/input`: mode-aware event mapping.
- `tui/view`: direct-cell rendering without rewrapping or remeasurement.
- `tui/mod`: signals, terminal lifecycle, driver boundary, and synchronous loop.
- `lib`: parse, validate, load, construct, and run orchestration.
- `main`: output and final exit-code mapping.

## 6. Coordinates and projection

Persistent identity is a `SourceOffset(u64)` measured from the beginning of the original file. A skipped leading BOM therefore places the first content byte at offset three, and CRLF retains its two-byte source range. Visual rows and columns are derived.

Layout segments extended grapheme clusters and uses the narrow `unicode-width` model. Each atom retains its source range, projection kind, and approved cell width.

Projection rules:

- LF, CRLF, and lone CR are structural and are never emitted.
- Tabs use four-column stops and remain indivisible source atoms.
- A tab too wide for an empty row becomes one replacement cell.
- C0 except LF/tab, DEL, and C1 controls become one replacement cell.
- A standalone zero-width grapheme becomes a dotted circle plus the source in one forced-width cell.
- A grapheme wider than the content width becomes one replacement cell until reflow has enough width.
- Spaces are neither trimmed nor collapsed.

Rendering writes the exact projected symbol and forced width directly to Ratatui cells. It does not call a second segmenter, width calculator, wrapping widget, or text widget.

## 7. Wrapping and viewport

Wrapping is greedy. It prefers the last fitting Unicode-whitespace boundary and otherwise breaks before the first non-fitting grapheme. Explicit LF always ends a row; blank and trailing lines remain addressable.

`WrapIndex` stores only content width, the absolute source range, and visual-row starts. Reflow reuses its allocation. An absolute source-byte anchor preserves reading position across resize. Explicit end following remains pinned to the last valid top row.

Progress is the visible source distance divided by readable source length, clamped below 100 until EOF. Empty documents report 100 percent.

## 8. Application behavior

The fixed interface has a header, body, status, and key-help row. Terminals below 16 columns or 4 rows show a clipped resize message, preserve state, and accept only resize and quit.

Navigation supports line, page, half-page, start, and end movement. `j`/`k`, arrows, paging keys, Vim-style control keys, Home/End, `g`/`G`, `q`, and keyboard Ctrl-C are mapped exactly by mode.

Search begins with `/`. Editing is separate from the committed query, Escape cancels, Enter commits, and an empty commit clears search. Drafts are limited to 4096 UTF-8 bytes; backspace removes one extended grapheme cluster.

Committed search is case-sensitive, literal, byte-preserving, and non-overlapping. The index stores one bit per readable source byte while exposing absolute `u64` match ranges. Initial selection intersects the first visible source offset, and `n`/`N` wrap forward or backward. Matches may cross soft rows; partial-grapheme intersections highlight the whole grapheme. The current match is reverse, bold, and underlined; other visible matches are reverse.

## 9. Terminal lifecycle

Argument and TTY checks precede signal installation. Retained handlers for SIGHUP, SIGINT, and SIGTERM record only the first signal. File loading and application construction then complete before terminal mutation.

Initialization marks cleanup before each step:

1. Enable raw mode.
2. Enter the alternate screen.
3. Hide the cursor.

The synchronous loop draws only when state changed, polls for at most 100 ms, reads at most one queued event, maps it, updates state, and repeats. Signals are checked around every initialization, poll, read, and restoration boundary.

Restoration attempts show cursor, leave alternate screen, and disable raw mode in reverse order. Failure never prevents a later cleanup attempt. The first restoration error is retained and combined with the primary error or signal. `Drop` is an idempotent fallback.

Exit status:

- 0: help, version, normal quit, or keyboard Ctrl-C.
- 1: file, terminal, allocation, render, event, or restoration error.
- 2: invocation error.
- 129, 130, 143: external SIGHUP, SIGINT, SIGTERM after successful restoration.

The restoration guarantee excludes SIGKILL, allocator abort, kernel failure, and terminal disappearance.

## 10. Resource policy

Loading, UTF-8 validation, reflow, and search construction are linear in source bytes. Persistent layout uses one `u64` row-start vector. Persistent search uses one bit per readable source byte. Ordinary render spans borrow source text; only a visible standalone zero-width grapheme owns a transient combined symbol. Large derived allocations use fallible reservation.

Threads, async execution, ropes, lazy paging, and benchmark infrastructure require measured need.

## 12. Verification

Unit tests cover argument parsing, diagnostic sanitization, loading and source coordinates, projection, wrapping, viewport math, search indexing, application state, input mapping, direct-cell rendering, and restoration error composition.

Process tests verify exact help/version streams, GNU diagnostics, exit status, `--`, non-terminal ordering, and control-safe arguments. Real bounded PTY tests verify normal quit, keyboard Ctrl-C, external SIGHUP/SIGINT/SIGTERM, cursor and alternate-screen cleanup, termios restoration, and pre-mutation file errors.

CI runs formatting, warnings-as-errors Clippy, stable Linux tests, Rust 1.88.0 Linux tests, and stable macOS tests with pinned action commits.

## 13. Non-goals

0.0.1 does not provide stdin content, redirected ANSI output, configuration, persistence, bookmarks, history, networking, HTML, Markdown semantics, format plugins, regex or fuzzy search, Unicode-normalizing search, localization, release automation, or compatibility with the removed browser.
