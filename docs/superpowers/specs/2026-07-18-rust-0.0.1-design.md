# TUT 0.0.1 Greenfield Rust Design

**Date:** 2026-07-18
**Status:** Approved design
**Target:** TUT 0.0.1

## 1. Decision and product direction

TUT restarts at version 0.0.1 as a greenfield Rust application. The previous C++ product does not define compatibility requirements for behavior, data, keybindings, architecture, or features. Existing Git commits remain the only historical record; uncommitted legacy work and legacy repository assets will not be archived or migrated.

TUT's long-term direction is a polished, local-first, multi-format terminal reader. Version 0.0.1 deliberately proves only one complete vertical slice:

```text
tut <PATH> → load local UTF-8 text → width-aware reflow → navigate and search in a safe TUI
```

The release must be useful as a plain-text reader without introducing speculative format or plugin architecture.

## 2. Product scope

### 2.1 Command-line interface

Supported invocations:

```text
tut <PATH>
tut -h
tut --help
tut -V
tut --version
tut -- <PATH>
```

The path is accepted as `OsString`/`PathBuf`, so a non-UTF-8 Unix path can still be opened. Display sanitization first applies `to_string_lossy`, then escapes U+0000–U+001F and U+007F as `\\xNN`, and U+0080–U+009F as `\\u{NNNN}`. Filename, path, and errors use that single-line form; UI elision happens grapheme-safely after escaping. Filesystem access always uses the original `PathBuf`.

Interactive path reading requires stdin and stdout to be TTYs. Stdin reading and redirected ANSI output are not supported in 0.0.1. Argument parsing happens first: exact help/version invocations write stdout and exit successfully without TTY checks or file access, and invocation errors write stderr and exit with code 2. For a path invocation, TUT validates both TTYs before opening the file. Terminal mutation begins only after the file has loaded successfully.

Supported release platforms are macOS and Linux.

### 2.2 File contract

TUT reads exactly one existing path that resolves to a regular file. Symlinks to regular files are allowed.

The raw input limit is 33,554,432 bytes (32 MiB) and is not configurable in 0.0.1. Loading creates an in-memory copy. Concurrent modification while reading is not guaranteed to produce a filesystem-atomic snapshot; after loading completes, the session uses an immutable copy and ignores later file changes.

Input normalization is ordered and deterministic:

1. Validate that the opened handle is a regular file.
2. Reject a known metadata length above the limit before buffer allocation.
3. Otherwise read no more than `limit + 1` bytes.
4. If the bytes read exceed the limit, return the size error before UTF-8 validation.
5. Reject invalid UTF-8 and report the first invalid raw-byte offset.
6. Remove exactly one leading UTF-8 BOM.
7. Convert CRLF and lone CR to LF.
8. Discard the raw buffer and retain one normalized `String`.

TUT never writes the source file, accesses the network, creates user data, or sends telemetry.

### 2.3 Visible capabilities

0.0.1 provides:

- Unicode-grapheme-safe, terminal-column-aware soft wrapping;
- reflow after terminal width changes while preserving a logical reading anchor;
- Vim-style and conventional navigation keys;
- literal search using `/`, `n`, and `N`;
- visible ordinary/current match highlighting;
- filename, sanitized path, reading progress, search status, and concise key help;
- clear startup/runtime errors and best-effort terminal restoration.

0.0.1 does not claim multi-format or Web support.

## 3. Cargo and dependency baseline

TUT is one Cargo package, not a workspace.

Package policy:

```toml
[package]
name = "tut"
version = "0.0.1"
edition = "2024"
rust-version = "1.88.0"
publish = false
license = "MIT"
```

The manifest also sets the repository URL. `Cargo.lock` is committed because TUT is an application. `rust-toolchain.toml` pins Rust 1.97.1 with rustfmt and Clippy for reproducible development; CI separately verifies the Rust 1.88.0 minimum.

Direct production dependencies:

- `ratatui 0.30.2`, default features disabled, `crossterm_0_29` enabled;
- `crossterm 0.29` for terminal modes and events;
- `unicode-segmentation 1.13` for extended grapheme clusters;
- `unicode-width 0.2` for terminal-column width;
- `signal-hook 0.3` for Unix signal flags;
- `rustix 1.x` with `fs` APIs for nonblocking open and opened-handle validation.

Initial development dependencies are `tempfile` plus `rustix 1.x` with `pty`, `termios`, and `process` features. The latter features are test-only and provide portable PTY creation, window sizing, terminal-attribute inspection, child signaling, and restoration assertions without relying on external shell utilities.

0.0.1 does not directly depend on Clap, `thiserror`, `anyhow`, `unicode-linebreak`, `textwrap`, regex, Tokio, Serde, a logging framework, a snapshot framework, or a benchmark framework. The CLI and small typed error enums are implemented with the standard library.

## 5. Architecture

### 5.1 Dependency direction

```text
main → lib
lib → cli / document / app / tui / error
app → document / layout / search
tui → app
error is a leaf imported where typed error conversion is required
```

No domain module imports `tui`, Ratatui, or Crossterm.

### 5.2 Module responsibilities

- `main.rs`: call the library entry point, print errors after terminal restoration, and return `ExitCode`.
- `lib.rs`: orchestrate CLI parsing, loading, `App` construction, and the TUI session.
- `cli.rs`: parse `args_os` and produce help, version, path, or invocation errors.
- `error.rs`: define typed errors, sanitized user messages, and exit-code mapping.
- `document.rs`: open, validate, bounded-read, UTF-8-check, and normalize a file.
- `layout.rs`: project normalized text to display atoms and build the visual-row index.
- `search.rs`: build and query a compact non-overlapping literal-match index and project visible matches.
- `app.rs`: own all reader state and implement deterministic `Action -> Outcome` updates.
- `tui/input.rs`: map Crossterm events and the current mode to semantic actions.
- `tui/view.rs`: render immutable state; it must not wrap document text a second time.
- `tui/mod.rs`: own terminal setup/restoration and the synchronous event loop.

### 5.3 Application state

`App` exclusively owns:

- immutable `Document`;
- optional width-derived `WrapIndex`;
- normalized-byte viewport anchor;
- `follow_end`;
- content width and body height;
- `Mode::Reading` or `Mode::SearchInput { draft: String, limit_hit: bool }`;
- committed query, compact match-start bitset, and current match range.

A 0x0 or otherwise unusably small terminal may have no valid `WrapIndex` until a usable resize arrives.

### 5.4 Architectural non-goals

0.0.1 does not define a `DocumentSource` trait, format registry, chapter/link model, repository layer, plugin interface, async service, or compatibility adapter. Future formats must first produce concrete requirements before changing the document model.

## 6. Text and coordinate model

### 6.1 Canonical coordinates

The normalized UTF-8 `String` is the only source of truth. Persistent logical positions are normalized byte offsets. The model uses explicit coordinate concepts:

- normalized byte offset: stable identity;
- extended grapheme cluster range: indivisible layout/render atom;
- display column: ephemeral width within one visual row;
- visual row index: width-derived and invalid after reflow;
- search range: normalized byte half-open range.

The 32 MiB cap makes `u32` normalized offsets safe.

### 6.2 Safe file opening

On macOS/Linux, loading uses a nonblocking read-only open that follows symlinks. The opened handle, rather than only the path, is checked to ensure it is a regular file. This prevents a path replacement with a FIFO from blocking forever before validation. Known oversize files are rejected before allocation, and a `limit + 1` read catches growth or stale metadata.

### 6.3 Display atoms

Layout and rendering share one `DisplayAtom` projection so width decisions cannot diverge.

- An entire extended grapheme cluster is measured with `UnicodeWidthStr::width`.
- LF is structural and is never emitted.
- Empty input yields one empty visual row.
- Consecutive LF and a trailing LF preserve their empty logical rows.
- Spaces are never trimmed or collapsed.
- A tab is one indivisible source atom. Its expansion width is `4 - (column mod 4)`. If it does not fit and the row is nonempty, wrapping occurs before it. If it is the first atom and the four-column expansion exceeds the content width, it is consumed and rendered as one `�` cell. A tab never creates an empty soft-wrapped row.
- C0 controls other than LF and tab, DEL U+007F, and C1 controls render as one `�` cell and never reach the terminal unchanged.
- A standalone zero-width grapheme renders as `◌` plus the original grapheme and counts as one project display column.
- A grapheme wider than the content width temporarily renders as one `�` cell; the original appears again after a wider resize.
- East Asian Ambiguous characters use the narrow-width policy.

The width guarantee is relative to TUT's single column-width model. Terminals and fonts may disagree for emoji or ambiguous-width characters; README documents this limitation.

## 7. Wrapping, viewport, and progress

### 7.1 Wrapping algorithm

Wrapping is a single forward greedy scan over display atoms:

1. Prefer the last Unicode-whitespace atom after which the row still fits.
2. If no whitespace break fits, break at the last fitting grapheme boundary.
3. Always consume at least one atom, including at width one.
4. Preserve every source character; soft wrapping neither trims nor inserts text.

Full UAX #14 language-sensitive line breaking is intentionally deferred.

### 7.2 Wrap index

`WrapIndex` stores strictly increasing `u32` visual-row start offsets and no copied text or per-grapheme objects. Rendering derives each row end from the next start or document end.

Reflow captures the logical anchor, clears and reuses the existing vector, uses fallible reservation, and never holds old and new worst-case indices simultaneously. This matters for a 32 MiB file containing almost only newlines, whose row-start index is roughly 128 MiB before allocator overhead.

### 7.3 Resize behavior

The viewport anchor is the desired normalized offset preserved across reflow. It starts at zero. After ordinary navigation or a search jump, it becomes the intended top-row start. Resize and height-only EOF clamping do not rewrite it solely because clamping changed the actual top row.

- If `follow_end` is true, the new top row is `max_top`.
- Otherwise choose the new row with the greatest start not exceeding the anchor, then perform one EOF clamp.
- At unusable geometry, preserve all logical state and do not use the index; an existing index may remain cached.
- On entering usable geometry, build or rebuild whenever the index is absent or its recorded width differs from the content width.
- A height-only change with an existing same-width index clamps the viewport without reflow.
- Only End/`G` or downward navigation that actually reaches the bottom sets `follow_end`.
- Upward navigation and search jumps clear or do not set `follow_end`.

EOF clamping may move a near-end anchor below the first visible row when a taller viewport would otherwise leave blank space.

### 7.4 Progress

Progress uses `visible_end`, the exclusive normalized byte offset immediately after the source interval covered by the last visible visual row:

- empty document or `visible_end == normalized_len`: 100%;
- otherwise `floor(100 * visible_end / normalized_len)`, clamped to 0–99%;
- intermediate arithmetic uses a wider integer type.

Progress is source-byte based so width changes do not redefine document progress.

## 8. TUI behavior

### 8.1 Layout

The fixed interface has no border or overlay:

1. one-row filename and sanitized, display-width-ellipsized path;
2. content body;
3. progress/search status row;
4. concise key-help row.

While editing a search, the status row displays `/draft` while retaining progress. Below 16 columns or 4 rows, TUT displays a clipped `terminal too small — resize` message, preserves logical state, and handles only quit and resize.

All 0.0.1 interface text is English; localization is deferred.

### 8.2 Keymap

| Action | Keys |
|---|---|
| Down one visual row | `j`, Down |
| Up one visual row | `k`, Up |
| Page down with one-row overlap | Space, PageDown, Ctrl-F |
| Page up with one-row overlap | `b`, PageUp, Ctrl-B |
| Half-page down/up | Ctrl-D, Ctrl-U |
| Document start/end | `g`/`G`, Home/End |
| Begin search | `/` |
| Next/previous match | `n`/`N` |
| Quit | `q`, Ctrl-C |

Reading-mode Esc is a no-op. Page movement is `max(body_height - 1, 1)`; half-page movement is `max(body_height / 2, 1)`.

Search-input mode accepts ordinary character input, removes the last extended grapheme with Backspace, commits with Enter, cancels with Esc, and quits with Ctrl-C. Other Ctrl/Alt combinations are ignored. Key Press and Repeat events are handled; Release, mouse, focus, and paste events are ignored.

## 9. Search semantics

Search is literal, case-sensitive, non-normalizing, and non-overlapping. For example, searching `aa` in `aaa` yields one match. Canonically equivalent composed/decomposed Unicode strings do not match unless their bytes match.

`Mode::SearchInput` owns `draft` and `limit_hit`. The committed query, match index, and current match remain unchanged until Enter.

- `/` starts an empty draft while the previous committed query remains active.
- Enter commits the draft.
- An empty committed draft clears search and its index.
- Esc cancels and restores the previous committed search unchanged.
- Backspace removes the last extended grapheme.
- The draft is limited to 4096 UTF-8 bytes. Rejected input sets `limit_hit`; a successful insertion or Backspace clears it; Enter or Esc leaves search-input mode.

On commit, `search.rs` performs one left-to-right non-overlapping scan and builds a compact match-start bitset keyed by normalized byte offset. One bit per source byte bounds the worst-case index to about 4 MiB at the document limit. Allocation is fallible. The state stores this bitset and the current match range, but no range vector, total count, or ordinal.

Initial selection uses the actual first visible row start, not the saved resize anchor. It chooses the first indexed match whose end is after that visible start, including a match that begins before but intersects it; otherwise it wraps. `n` and `N` scan indexed starts after/before the current range and wrap. A search jump places the selected match near the body center when possible and updates the viewport anchor to the resulting intended top-row start.

Rendering visits only indexed matches that intersect the visible source interval. Ordinary visible matches use reverse video. The current match uses reverse, bold, and underline. A match intersecting part of a grapheme highlights the entire grapheme. Status displays the query, `no matches`, or the draft-limit message; it does not display a count or ordinal.

## 10. Event and terminal lifecycle

### 10.1 Event loop

The event loop is synchronous: draw, wait with Crossterm poll intervals of at most 100 ms, read/map an available event, update, and repeat. The recorded signal is checked before and after every poll/read and after each terminal-initialization step; a poll timeout checks signals without forcing a redraw. An interrupted poll or read with a recorded signal becomes signal exit.

Resize events are processed strictly in queue order, one event per loop iteration. TUT does not drain ahead, debounce, buffer, drop, or replay later keyboard events. There is no async runtime or background thread. An unchanged content width does not trigger reflow unless the wrap index is absent.

### 10.2 Exit codes

- `0`: help, version, normal quit, or keyboard Ctrl-C;
- `2`: invocation error;
- `1`: path, file, UTF-8, size, allocation, TTY, draw, event, or restoration error;
- external SIGHUP/SIGINT/SIGTERM: 129/130/143 after successful restoration.

The runtime retains both the primary outcome and the first restoration error. If restoration fails, it emits one combined sanitized error line and exits 1, including when the primary outcome was a signal. Otherwise startup/runtime errors use 1, external signals use 129/130/143, and normal completion uses 0.

All non-help/version diagnostics write exactly one sanitized `error: ...` line to stderr after any applicable restoration. Invocation errors also include `usage: tut <PATH>`.

### 10.3 TerminalSession protocol

All CLI, path, file, and TTY validation completes before terminal mutation. Signal handling is installed before the first mutation and handlers only record the signal.

The session then:

1. enables raw mode;
2. enters the alternate screen;
3. hides the cursor.

Each non-transactional step is marked cleanup-needed before invocation because output may have been emitted even if flushing reports failure.

Restoration attempts every applicable step in reverse order. Failure in one cleanup step never prevents later cleanup; the first restoration error is retained. Normal paths restore explicitly before reporting errors. `Drop` is an idempotent fallback for returned errors and unwind panics. TUT keeps `panic=unwind`, installs no custom global panic-reporting framework, and interprets an interrupted event read with a recorded signal as signal exit.

The guarantee excludes SIGKILL, allocator abort, kernel failure, terminal disappearance, and panic-message ordering.

## 11. Testing strategy

### 11.1 Loader tests

Cover missing paths, regular files, symlinks, directories, FIFOs/devices where supported, empty input, BOM placement, LF/CRLF/CR, invalid UTF-8 offsets, exactly 32 MiB, limit plus one, and growth beyond prior metadata. Tests inject smaller limits where practical; the production CLI exposes no override.

### 11.2 Layout invariants

Table tests cover ASCII, repeated spaces, long words, blank/trailing lines, CJK/fullwidth text, combining graphemes, ZWJ emoji, flags, tabs at different columns, control replacements, zero-width and over-wide graphemes, width one, and a very large combining grapheme.

Assertions verify valid UTF-8/grapheme boundaries, strictly increasing starts, deterministic rebuilding, complete source coverage, termination, and row widths within TUT's model.

### 11.3 State and search tests

Cover line/page/half-page movement, clamping, top/bottom, empty and short documents, `follow_end`, 0x0/tiny dimensions, narrow-wide-narrow reflow, near-EOF resizing, query edit/cancel/clear, non-overlapping match-index construction, no-match behavior, forward/backward wrapping, matches crossing soft rows, visibility after jumps, and match stability after resize. Include a phase-sensitive case such as `aaaaaa` with query `aa` and a viewport beginning at byte 3 or 4 to prove rendering uses the global non-overlapping index rather than inventing locally phased matches.

### 11.4 Input and rendering tests

Verify every key alias, modifiers, mode differences, and ignored events. Ratatui `TestBackend` direct buffer/style assertions cover normal, search-input, draft-limit, no-match, current-match, empty-file, path-elision, 100%-progress, and tiny-terminal frames. Path tests include ESC, LF, DEL, C1 controls, and non-UTF-8 Unix bytes. Control characters must never reach the rendered buffer unchanged. No snapshot framework is required.

### 11.5 CLI and terminal tests

Process tests cover help/version, missing/extra/unknown arguments, `--`, non-TTY use, and file errors before alternate-screen output. A recording fake terminal exercises partial initialization, repeated restoration, first-cleanup-step failure, draw/event failures, and signal exit; no production fault-injection interface is added.

Automated PTY integration cases run under `cargo test` with bounded timeouts in both Ubuntu and macOS CI jobs. They cover normal quit, key Ctrl-C, external SIGTERM, resize, cursor visibility, echo, raw mode, and alternate-screen restoration.

## 12. Performance policy

0.0.1 freezes structural bounds rather than hardware-specific timing targets:

- loading and normalization are O(n) in source bytes;
- complete width reflow is O(n) in source bytes;
- rendering is proportional to visible source bytes and visible match work;
- no second normalized full-text copy;
- no simultaneous old/new worst-case wrap indices;
- fallible capacity reservation for large derived structures.

A single grapheme may contain many source bytes, so rendering complexity is not stated only in terms of visible row count. Threads, async, ropes, lazy paging, and benchmark infrastructure are added only after measurement identifies a real bottleneck.

## 13. CI and documentation

CI uses pinned GitHub Action commit SHAs with version comments and concurrency cancellation.

Three jobs run on pull requests and default-branch pushes:

1. Ubuntu with the pinned reviewed stable toolchain: `cargo fmt --check`, Clippy with `-D warnings`, and tests.
2. Ubuntu with Rust 1.88.0: tests.
3. macOS with the pinned reviewed stable toolchain: tests.

0.0.1 does not add coverage gates, nightly, Miri, fuzzing, automatic benchmarks, release automation, or repeated release builds.

`README.md` is the user-facing contract: scope, installation/build, `tut <PATH>`, keymap, file limits, platform/TTY assumptions, errors, width limitations, and non-goals. `docs/architecture.md` records dependency direction, state invariants, `DisplayAtom`, resize semantics, and terminal lifecycle without duplicating the user guide.

## 14. Legacy repository replacement

The user explicitly authorized complete removal of all uncommitted legacy work without an archive. Existing Git commits are the sole retained history. No archive branch, stash, bundle, migration directory, or compatibility layer is created.

Implementation deletes:

- `CMakeLists.txt` and `cmake/`;
- `assets/`;
- `test_browse.sh`;
- `KEYBOARD.md`, `STATUS.md`, and `CONTEXT.md`;
- the current legacy `src/` and `tests/` contents;
- old ADRs and old GitHub workflows;
- every remaining C/C++, CMake, Clang, browser, theme, history, bookmark, and legacy build artifact.

`README.md` and `.gitignore` are rewritten. `LICENSE` and Git history are retained. This approved specification remains under `docs/superpowers/specs/`; new Rust architecture documentation is created separately.

All tracked deletions and rewrites must appear in the staged diff. Untracked or ignored legacy files are first listed in an explicit inventory and then removed directly; they are never added, stashed, bundled, or archived. A final allowlist audit verifies that the repository surface matches section 4. Implementation does not use `git reset --hard`, orphan the repository, or reinitialize Git.

## 15. Explicit non-goals

0.0.1 excludes:

- Markdown semantics, ebooks, and other format parsers;
- Web, HTTP, HTML, links, chapters, and tables of contents;
- configuration, themes, configurable keybindings, and localization;
- persistence, reading-position restore, bookmarks, and history;
- mouse input and stdin reading;
- async loading, threads, file watching, and background tasks;
- plugins, source registries, format traits, and compatibility adapters;
- regex, fuzzy, case-insensitive, or Unicode-normalizing search;
- old data, behavior, or keybinding migration;
- release automation and package-manager distribution.

## 16. Implementation increments

1. Remove the legacy product surface and create the single-package Cargo skeleton.
2. Implement CLI, typed errors, bounded file loading, and normalization with tests.
3. Implement display atoms, wrapping, compact indexing, viewport anchoring, progress, and resize tests.
4. Implement the pure application state machine, navigation, and search with tests.
5. Implement Ratatui rendering, event mapping, terminal lifecycle, and deterministic UI tests.
6. Complete pathological-input checks, PTY verification, README, architecture documentation, and CI.

Each increment must pass its relevant tests before the next begins.

## 17. Definition of done

TUT 0.0.1 is complete when:

- the repository has no legacy C++, CMake, browser, theme, history, bookmark, or old workflow artifacts;
- package, help, version, README, and architecture documentation consistently identify 0.0.1;
- `tut <PATH>` opens every valid file covered by the file contract;
- all navigation, resize, search, highlighting, progress, tiny-terminal, error, exit-code, and restoration behavior in this specification is implemented;
- automated loader/layout/state/search/input/render/CLI tests pass;
- macOS/Linux PTY restoration checks pass;
- all three CI jobs pass with no warnings;
- no explicit non-goal has been partially introduced.
